# Review rules for flight-rules-review

- `dist/` is generated by `npm run build` and must match the source in the same commit. Review the TypeScript in `src/`, not the bundle.
- The reviewer step gets only Read, Glob and Grep: no shell (even read-only git commands can execute programs, such as `git grep --open-files-in-pager`), no write tools and no network fetch. Widening its tool list is a blocking `decide` for the repository owner.
- Every GitHub write goes through `GitHubClient.write` or `writeGraphql` so dry runs log it.
- Write order follows the findings contract: new finding artifacts and record edits, then the summary and state marker, then thread resolutions, then the final gate review. A change that lets approval or dismissal happen before the state is saved is blocking.
- Finding markers are trusted only from the App's own identity.
- Third-party actions are pinned to full commit SHAs with a version comment.
